为什么选 AgentYard

智能体不止是 prompt。

协作模型

人和 Agent 都是参与者；Task 记录目标、事实、决定和成果，组织提供灵活的成员与权限结构。

集成

工具连接器与通道提供方位于协议边界之后，将厂商鉴权、签名、厂商 SDK 与长连接隔离在智能体逻辑之外。

运维

每个 Agent 拥有持久 Session。消息触发有界执行，定时器、事件订阅和长期工具运行让工作在后台持续推进。

核心模型

简单的核心概念，组合复杂的工作。

  • 参与者：人 + Agent
    • Session · 持续的私有上下文
    • Task · 共享目标与工作记录 事实 · 决定 · 进展 · 成果
  • 独立版本化的配置
    • 角色 · 模型 · 工具 · Skill · 知识 · Playbook

Session 是 Agent 的持续上下文实例，Task 是参与者共享的工作记录。角色模板提供版本化提示词、模型与能力引用，入口独立授予权限；智能体通过消息、共享上下文和受控工具协作。

  • 实例保留自己的上下文，重要工作信息进入 Task 供参与者共享。
  • 角色、模型、工具、Skill、知识与 Playbook 独立版本化，运行实例固定引用。
  • 工具执行时检查实际授权，模板不能自行授予权限。

运行时架构

持续上下文，有界执行，长期协作。

  1. 控制平面

    协作与授权

    Spring Boot API 管理参与者、Task、消息、Session 与授权，按模板版本装配执行上下文。

    Spring Boot · PostgreSQL
  2. 工作流 Worker

    可恢复编排

    Temporal 承载 Agent Activation 和 Playbook ToolRun，处理执行、等待、恢复与取消。

    Temporal · JVM worker
  3. 智能体运行时

    决策与执行

    Python 读取实例上下文，调用模型与受控工具，保存完整运行记录并提交回复和工作记忆。

    Python · LLM 提供方
  4. 知识服务

    检索面

    URL 与文件被解析为文档，构建索引快照，再由独立知识版本提供检索。

    Python · 向量索引

扩展面

工具与通道的统一边界。

工具连接器

业务能力接入

扩展服务通过 manifest 暴露工具操作 schema，AgentYard 负责把智能体运行时的工具调用路由到对应连接器。

通道提供方

会话通道接入

通道提供方在通道网关一侧归一化 IM、工单与服务台入站事件，并消费出站消息帧。

协议 + SDK

契约优先的扩展开发

OpenAPI、JSON Schema、示例、标准 fixture 及 JVM / Python Extension SDK 让扩展服务与平台边界保持一致。

开发者入口

从公开契约开始。

01 快速上手 在本地运行控制平面、运行时、知识服务与控制台。 02 架构 应用拆分、运行时流转，以及当前实现边界。 03 扩展集成 基于扩展面构建工具连接器与通道提供方。 04 扩展协议 以 OpenAPI、JSON Schema、示例与 fixture 作为单一可信源。

项目状态

Alpha 阶段，面向评估与本地集成。

AgentYard 正围绕持续接待、持久 Agent 实例、Task 共享上下文与可恢复执行完善实际协作体验。项目处于 Alpha 阶段，接口和数据结构仍可能直接调整。
