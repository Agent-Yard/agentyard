为什么选 AgentYard

智能体不止是 prompt。

治理

业务域、场景、助手、智能体、playbook、知识库与资源均作为一等治理对象建模。

集成

工具连接器与通道提供方位于协议边界之后，将厂商鉴权、签名、厂商 SDK 与长连接隔离在智能体逻辑之外。

运维

会话、事件、playbook 运行、人工转交与共享状态全程持久化，并以面向真实业务的运行时视图呈现。

核心模型

一棵贯通运行时的治理树。

  • 业务域
    • 场景
      • 助手发布 发布锚定
        • Owner 智能体
        • Playbook
        • 资源 工具 · 技能 · 模型 · 知识

AgentYard 把配置视为契约。草稿对象可以持续演进，但运行中的会话锚定在一个已固化 Owner 智能体、策略、资源版本、知识绑定与 playbook 定义的助手发布上。

  • 发布快照避免运行期配置漂移。
  • 工具、技能、模型与知识都带有稳定的资源版本锚点。
  • 智能体做决策，playbook 执行结构化业务流程。

运行时架构

以会话为中心、可恢复的工作流执行。

  1. 控制平面

    发布装配

    Spring Boot API 装配发布、治理目录，并对外暴露会话运行时视图。

    Spring Boot · PostgreSQL
  2. 工作流 Worker

    可恢复编排

    Temporal 承载会话与 playbook 工作流，处理等待、恢复、人工转交与共享状态。

    Temporal · JVM worker
  3. 智能体运行时

    决策与执行

    Python 执行 Owner 轮次、工具任务、隐私策略处理与知识调用。

    Python · LLM 提供方
  4. 知识服务

    检索面

    URL 与文件来源被切分为 chunk，生成索引快照，按发布维度做检索。

    Python · 向量索引

扩展面

工具与通道的统一边界。

工具连接器

业务能力接入

扩展服务通过 manifest 暴露工具操作 schema，AgentYard 负责把智能体运行时的工具调用路由到对应连接器。

通道提供方

会话通道接入

通道提供方在通道网关一侧归一化 IM、工单与服务台入站事件，并消费出站消息帧。

协议 + SDK

契约优先的扩展开发

OpenAPI、JSON Schema、示例、标准 fixture 及 JVM / Python Extension SDK 让扩展服务与平台边界保持一致。

开发者入口

从公开契约开始。

01 快速上手 在本地运行控制平面、运行时、知识服务与控制台。 02 架构 应用拆分、运行时流转，以及当前实现边界。 03 扩展集成 基于扩展面构建工具连接器与通道提供方。 04 扩展协议 以 OpenAPI、JSON Schema、示例与 fixture 作为单一可信源。

项目状态

Alpha 阶段，面向评估与本地集成。

AgentYard 已经打通 控制平面 → 发布快照 → Temporal worker → Python 运行时 的核心链路。在面向生产的强化过程中，接口、数据结构与配置在小版本间仍可能调整。
