# 运行时会话消息模型重构：消息一等公民，事件回归状态流

**Summary**
- 直接把运行时会话从“`SessionEvent.payload` 混装消息内容”重构为“两层模型”。
- `SessionMessage` 成为用户可见内容的唯一载体，支持 `TEXT`、`IMAGE`、`RICH_TEXT`、`CARD` 四类 block，可在一条消息中混排多个 block。
- `SessionEvent` 只保留工作流/状态类事件，不再承载用户正文或助手正文；运行时页面改为主区域展示 `messages`，旁路展示 `events`。
- 不做兼容层、不保留旧的 message-in-event 双写逻辑；新模型上线后，运行时读写、SSE、agent runtime、前端渲染全部统一到新结构。

**Key Changes**
- 在 `packages/contracts` 和 `packages/contracts-jvm` 引入新公共类型：
  - `SessionMessage`
  - `SessionMessageInput`
  - `SessionMessageRole`
  - `SessionMessageStatus`
  - `SessionMessageSender`
  - `SessionMessageBlock = Text | Image | RichText | Card`
  - `RichTextFormat` 仅保留 `MARKDOWN`
  - `CardAction` 仅支持 `LINK`
- `SessionRuntimeDetail` 改为返回 `session + messages + events + playbookRuns`；SSE `SessionRuntimeStreamEvent.detail` 同步改为新 shape。
- `SessionRuntimeSession` 增加 `latestMessageSequence`；`SessionRuntimeChangeStamp` 和 SSE fingerprint 改为同时包含 `latestMessageSequence + latestEventSequence + latestPlaybookRunUpdatedAt`。
- API 输入统一改为结构化消息：
  - `CreateSessionRequest.openingMessage?: SessionMessageInput`
  - `SendSessionMessageRequest.message: SessionMessageInput`
  - `HumanOperatorReplyRequest.message: SessionMessageInput`
  - 控制台现有文本输入框继续保留，但提交时包装成单个 `TEXT` block。
- `SessionEventType` 删除消息类事件：`USER_MESSAGE`、`OWNER_REPLY`、`HUMAN_OPERATOR_REPLY`；保留纯状态类事件，如 `OWNER_SWITCH`、`PLAYBOOK_*`、`AGENT_TURN_FAILED`、`SESSION_HUMAN_HANDOFF_*` 等。
- `SessionEvent` 增加 `relatedMessageId`，仅在事件需要关联某条可见消息时填写；`payload` 只保存状态上下文，不再放消息正文。
- 持久化新增 `session_runtime_message` 作为运行时消息唯一真源，字段固定为：
  - `message_id`
  - `session_id`
  - `sequence`
  - `role`
  - `sender_type`
  - `sender_id`
  - `sender_name`
  - `status`
  - `blocks jsonb`
  - `metadata jsonb`
  - `related_playbook_run_id`
  - `related_owner_agent_id`
  - `source_event_id`
  - `created_at`
  - `updated_at`
- `SessionRuntimeStore` / repository / worker persistence activities 增加 `listMessages`、`nextMessageSequence`、`appendMessage`；`appendEvent` 只处理系统事件。
- `SessionWorkflowImpl` 引入统一的 `appendMessage(...)` 帮助方法，所有用户消息、owner 回复、人工回复、系统回复都走消息表；事件只在 owner 切换、playbook 状态变化、turn 失败、handoff 等场景产生。
- `AgentDecision` 和 prompt response contract 改为结构化输出：
  - `replyMessage` 取代 `replyContent`
  - `accompanyingMessage` 取代 `accompanyingReply`
  - 两者类型均为 `SessionMessageInput`
- `AgentTurnRequest` 改为同时携带：
  - `recentMessages`
  - `recentEvents`
  - `trigger`
  - `triggerMessageId`（用户消息触发时必填，非消息触发为空）
- `agent-runtime` 的 prompt 组装不再从 `recentEvents.payload.text` 取消息历史，而是从 `recentMessages` 渲染语义上下文：
  - `TEXT` 直接透传
  - `RICH_TEXT(MARKDOWN)` 以 markdown 文本透传
  - `IMAGE` 渲染为稳定文本描述，包含 `alt/url/mimeType`
  - `CARD` 渲染为稳定文本描述，包含 `cardType/version/data/actions`
- `apps/web` 运行时页面改为两个面板：
  - `Messages`：按消息 role 渲染 block 列表
  - `Session Events`：继续展示系统事件时间线
- 前端 block 渲染规则固定：
  - `TEXT`：纯文本
  - `IMAGE`：图片预览
  - `RICH_TEXT(MARKDOWN)`：安全 markdown 渲染
  - `CARD`：按 `cardType + version + data + LINK actions` 渲染为只读卡片，按钮仅跳转，不回传 session
- OpenAPI 同步更新为新 schema，并让 TypeScript contracts、JVM contracts、前端类型保持完全一致。

**Test Plan**
- contracts / OpenAPI round-trip：新增消息与 block schema 后，TS/JVM/OpenAPI 三端序列化一致。
- repository/store：可持久化并按顺序读取 `session_runtime_message`，`latestMessageSequence` 与 change stamp 正确更新。
- `SessionRuntimeService`：创建会话、发送消息、人工回复都写入 message；状态事件不再承载正文。
- `SessionRuntimeStreamService`：仅 message 变化也会触发 `SESSION_UPDATED`，SSE detail 含最新 `messages`。
- `SessionWorkflowImpl`：用户消息触发 turn、owner 回复、决策拒绝的系统回复、handoff 期间人工回复都走 `appendMessage`；状态事件和消息分离。
- `agent-runtime`：
  - prompt history 使用 `recentMessages`
  - `triggerMessageId` 能定位当前用户消息
  - 结构化 `replyMessage/accompanyingMessage` 能被正确解析
  - image/card/rich text block 能稳定转成 prompt 文本
- `apps/web`：
  - `Messages` 面板正确渲染 text/image/markdown/card
  - `Session Events` 面板不再显示用户/助手/人工正文
  - 现有文本发送表单仍能工作，并提交为单个 `TEXT` block
- 集成测试覆盖：
  - 创建会话带 opening message
  - 发送用户消息
  - 人工回复
  - playbook/owner 事件与消息并存
  - SSE 快照与更新都返回 `messages + events + playbookRuns`

**Assumptions**
- 不做旧 `SessionEvent.payload.text` 到新消息表的数据回填；历史数据不兼容处理。
- 不复用 `conversation_message` 作为 runtime canonical store；运行时消息唯一真源是 `session_runtime_message`。
- v1 富文本唯一标准是 `RICH_TEXT.format = MARKDOWN`。
- v1 图片块只保存 URL/引用和元数据，不支持在消息体内直接传 Base64。
- v1 卡片动作只支持 `LINK`，不引入卡片提交/回调事件。
- 这次只做“结构化消息 API + 存储 + 渲染 + agent runtime 闭环”，不做运行时控制台里的图片上传器、富文本编辑器、卡片搭建器；控制台继续用文本框提交 `TEXT` block。
