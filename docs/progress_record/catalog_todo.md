# Catalog TODO

## 1. 批量引用分析

现状：

- 当前已经补齐业务域、场景、助手、智能体、资源和资源版本的删除约束
- 但引用检查仍主要发生在“单对象删除时”的同步校验阶段
- 前端能看到局部绑定关系，还不能对一个对象做全量下游引用分析

后续目标：

1. 为 domain / scenario / assistant / agent / resource 提供统一的引用分析接口
2. 支持返回直接引用与间接引用链，例如：
   - 资源 -> 智能体绑定 / 智能体执行策略 / 助手默认策略
   - 助手 -> 智能体 / 编排 / 发布快照 / 私有资源
   - 场景 -> 助手 / 运行入口
3. 支持批量分析多个对象，给治理页面和后续批量操作复用

## 2. 删除前影响预览

现状：

- 删除动作当前已经会被后端正确拦截
- 但用户是在点击删除之后才知道“为什么不能删”
- 缺少一个显式的删除前影响预览面板

后续目标：

1. 在删除确认前先展示影响摘要，而不是只在失败后提示错误
2. 影响预览至少要包含：
   - 会阻止删除的对象清单
   - 删除后会被自动回收的对象清单
   - 是否影响当前发布快照 / 编排 / 资源版本锚点
3. 为批量删除预留统一预览结构，避免后续再次设计一套协议

## 3. 软删除与归档视图

现状：

- 当前控制面仍以硬删除为主
- 删除后对象直接从主视图消失，不利于审计、恢复和治理追踪
- 发布快照虽然保留，但缺少“已归档对象”的统一视图

后续目标：

1. 为核心目录对象引入 `ACTIVE / ARCHIVED` 之类的生命周期状态
2. 控制台支持主视图隐藏归档对象，并在归档视图中单独查看
3. 为归档对象保留：
   - 基础元数据
   - 删除人 / 删除时间 / 删除原因
   - 删除前引用快照
4. 明确“软删除、归档、彻底清理”三者的边界，避免审计与治理信息丢失
