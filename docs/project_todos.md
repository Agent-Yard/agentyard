# 项目待办与优先级

更新：2026-10-25。Agent 协作主链已实现，并补充试用发现的消息去重、明确结束、自动续执行、实际运行状态及提交版本保护。当前运行行为见[代码现状](architecture/code-framework.md)和[运行收敛机制](architecture/activation-completion.md)。

## 1. 当前基线

主设计：[Agent 持续上下文与人机协作](architecture/agent-collaboration.md)。已实现范围见[实施与验收基线](architecture/collaboration-acceptance.md)，具体运行证据和尚未联调的外部账户见[验收记录](architecture/collaboration-verification.md)。完成的改造不再作为待办重复维护。

下一步优先收集真实业务试用反馈，并在具备测试账户后验证实际 OIDC、渠道及业务工具接入；据此决定组织、知识和运营能力的扩展顺序。

## 2. 后续工作

### 组织与治理

- 基于新主体和资源引用补充归档、恢复、删除原因、删除影响预览和批量操作。
- 模板、工具、知识与流程版本的 diff、影响范围、回滚和有需要时的灰度；围绕实际能力引用独立管理。
- 组织预算、职责排班、复杂确认责任交接与治理视图，依据实际使用场景扩展。
- 多租户部署及数据隔离产品化另行设计；组织成员关系不自动等于租户隔离。

### 知识与成果质量

- 召回评估、不同索引快照对比、相关性与噪声分析、embedding/chunk 策略实验。
- 按真实来源变化需求补自动重导入与索引策略，继续复用既有 source/job/document/snapshot 模型。
- 提炼可复用的工作成果时保留来源、权限和版本，不将私有 Session 自动汇入共享知识。

### 运行与生产交付

- 基于新链路整理部署探针、优雅退出、Worker drain、TLS、凭证注入和外部依赖运维。
- 统一 trace 与指标，按 Session、Task、Activation、ToolRun 定位问题；已有 traceparent 和结构化日志可以复用。
- 长历史分页和基本恢复在当前主线实现；高级诊断、趋势、SLO 和容量规划随后补充。
- PostgreSQL、对象存储及 Temporal 持久状态的备份与恢复演练；按实际部署拓扑设计，不把 visibility 索引视为完整执行备份。
- 多 API/Worker 实例、Redis 故障和投递恢复专项验证；基础取消、恢复、授权、幂等不能推迟到此阶段。
- 测量真实瓶颈后优化查询、连接池、向量索引、页面加载和缓存，避免提前引入另一套基础设施。

### 用量与成本

- 基于已保存的 Session、参与者、Activation、Task 和模板版本用量，补充 ToolRun 节点归因和面向用户的成本分析。
- 先提供必要执行容量和预算限制，再建立组织成本分析与配额策略。
- 达到预算上限要形成可解释的等待或失败记录，不伪造任务完成。

## 3. 维护约定

新增需求先检查是否属于当前验收基线，缺陷直接修复并补验证；扩展需求写入本页或 `docs/todo/` 的详细计划。完成状态以代码和验证证据为准。`docs/doing/` 只保存正在进行的执行记录，完成自查后清理。
