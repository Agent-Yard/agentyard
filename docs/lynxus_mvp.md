## 当前阶段判断

当前代码库已经不再只是 MVP 概念验证，更接近：

- 单租户默认的多智能体平台原型
- 可本地联调的 Alpha 阶段产品骨架
- 具备真实发布快照、运行编排和人工恢复能力的演示系统

它已经超过了“只验证主树模型是否成立”的阶段，因为下面这些能力都已经落地：

- 目录配置：业务域、场景、助手、智能体、资源和绑定
- 发布冻结：资源锚点、agent 执行配置和图快照
- 资源治理：资源目录、资源版本发布、生效版本和引用分析
- 运行编排：`START / AGENT / HUMAN / END` 显式图执行
- 长流程托管：Temporal `start / signal / resume`
- 运行观测：任务、流程、节点、人工介入、tool 调用与工具结果摘要
- 资源模型：知识库、Tool、LLM 模型和 Skill 四类资源已打通

## 当前已验证的核心问题

### 1. 分层模型已经可执行

不是停留在纸面模型，而是已经可以从业务场景一路落到助手发布、资源锚点和运行实例。

### 2. 运行模型已经成立

系统不是固定问答链路，而是基于发布图的真实多节点运行，且支持人工节点暂停与恢复。

### 3. 资源复用模型已经落地

资源不再只是概念定义，而是可以被版本化、绑定、冻结并在运行时解析使用。

当前这一层已经收敛到“资源版本 + 助手发布 + agent 执行策略”的组合，不再依赖独立 Prompt Template 资源。

## 当前仍然保留的原型边界

虽然已经超出 MVP，但距离生产化平台还有明显差距：

- 认证仍是 mock 方案，未接真实 OIDC / IAM
- 部分运行态对象仍保存在 API 内存结构中
- `agent-runtime` 仍保留 `demo.local` 的本地闭环适配
- workflow 启动入口仍同步等待首个结果，观测链路还不够稳健
- Redis / MinIO 仍主要处于“基础依赖已接入、业务承载待补齐”的阶段
- 生产级审计、安全隔离、灰度发布、SLO 和成本治理还没补齐

## 当前阶段更合适的目标表述

如果要对外描述当前仓库，建议统一使用下面这类说法：

**Lynxus 当前是一套面向企业智能体协作的单租户默认平台原型，已经具备配置治理、资源版本化、发布快照、图编排执行和人工介入闭环能力，下一阶段重点补齐运行态持久化、权限治理和生产化观测能力。**

## 近阶段重点

- 把 workflow 首结果同步等待改成异步观测链路
- 补齐运行态持久化与查询能力
- 明确 seed / demo 模式与真实运行模式的边界
- 明确 Redis / MinIO 等基础依赖在正式架构中的职责
- 引入真实身份体系与更细粒度权限控制
- 强化失败可观测性、错误语义和测试 / CI 体系
- 补齐治理控制面的批量引用分析、删除前影响预览，以及软删除与归档视图
