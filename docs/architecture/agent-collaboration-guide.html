01
The core model

用少量概念，表达复杂协作。

人和 Agent 是参与者。Session 让 Agent 拥有持续身份与私有上下文；Task 汇集共享工作信息；资源通过获授权的工具被读取和使用。

Shared work

Task 保存共同工作的事实。

它可以是一项交付、一次调研，也可以是一项长期职责。目标、参与者、资料、问题、成果和决定都沿着它组织。

Task 没有自己的判断力执行者判断能否提交，发起者判断能否接受。系统记录动作、检查权限和版本。
同一模板 → 多个独立实例

两位“研究员”可以采用相同角色定义，但拥有不同身份、记忆与授权。

一个 Task ↔ 多个 Session

默认让执行实例专注一项工作；机制允许它参与多项有关联的工作。

一次激活 ≠ 一项工作完成

Activation 明确区分完成、等待和受阻；中断可按检查点自动续执行。Session 和 Task 可以继续长期存在。

04
Roles describe. Tools enforce.

角色定义工作方式，授权约束实际操作。

角色模板提供职责和预设上下文。真正读写数据、调用工具、通信、创建实例或授予权限时，服务端检查当前主体、操作与目标对象。

模板可以描述“研究供应商”，但不会因此自动拿到全部业务系统、其他 Session 或确认人的权限。

示意当前校验边界；不同工具对应不同的对象权限和授权条件。

人委托的根工作

人提出目标→Agent 创建 / 执行→人最终确认

代理确认记录：决定者 = 人，执行者 = Agent，依据 = 当前真实人类消息 + Task + 成果版本。

Agent 自行拆分的子工作

Agent 发起→其他实例执行→发起 Agent 确认

子工作完成不自动完成根工作。确认责任可以显式转交，阶段确认也不会自动结束长期职责。

05
Persistence without permanent compute

实例可以长期存在，计算资源按需运行。

Session 的持续存在、一次 Activation 的结束、一个工具的等待和 Task 的完成，分别表达不同的事实。工作暂停或等待时，身份和记录仍然保留。

四类输入，都能推进原实例。

参与者消息订阅变化定时到期工具结果

输入先持久化，再调度。单个 Session 同时只推进一个 RUNNING Activation；其他实例和长工具可以并行。

暂停保留输入；恢复先核对回执。取消后的迟到结果留作证据，不重新启动已终止的工作。

06
Organization emerges from relationships

协作关系可以长成不同的组织形态。

组织维护成员、角色、共享资源和授权。具体工作由 Task 连接起来。协调、执行、审阅和确认关系可以组合，消息无需固定经过单一中枢。

这些结构展示当前基础机制的组合方式。完整企业组织管理、排班、复杂交接和成本治理仍属于后续产品化范围。

07

同一条运行链，连接前台与后台。

08
A working foundation

这版实现，已经把协作闭环连接起来。

当前是可运行的 alpha。真实模型和浏览器验证过连续接待、独立委派、专业实例直接问答、返工、重新提交和人的最终确认。

本版已经落实

  • 具体参与者身份、持续 Session、有界 Activation。
  • 独立版本化的角色、入口、模型、工具、知识与流程。
  • Task 共享内容、来源与版本、实际可读取的成果引用。
  • 实时工具授权、直接通信、持久投递、定时与订阅。
  • 人的代理决定、成果返工、阶段确认及责任记录。
  • 真实上下文存储、流程等待与恢复、取消后的回执保留。

仍有清晰的产品边界

  • 完整组织治理、多租户交付、排班和高级预算尚待扩展。
  • OIDC、飞书企业账号与第三方生产账号未完成本次在线联调。
  • 组织形态示意是机制组合，不是已上线的企业管理产品。
  • 模型可能理解偏差；明确授权、证据和最终确认仍然必要。

人和 Agent 以参与者身份行动，
以 Task 组织共同目标，
以持续上下文保留工作连续性。

组织方式可以变化，底层协作规则保持一致：各自拥有上下文，按权限共享信息，通过工具采取行动，让成果和决定有据可查。
