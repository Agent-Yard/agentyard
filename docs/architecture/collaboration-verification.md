# Agent 协作架构验收

日期：2026-10-05。对应[架构决策 D01—D21](agent-collaboration.md)和[工作包 W01—W08](collaboration-acceptance.md)。本文记录当前实现的验证范围；真实模型、确定性端到端、真实数据库集成和外部账户联调分别说明。

## 1. 验证环境与真实性

跨语言场景运行真实 Spring/Jooq 事务、隔离 PostgreSQL、实际 Redis、Temporal 测试服务及生产 Worker、独立 Python Runtime 进程和 HTTP 工具。Runtime 启用完整 lifespan、transcript 与工具回执。测试模型只决定下一步调用；业务效果由真实 API、授权、调度和数据库产生，没有直接写入预期成果。

真实模型使用用户授权的 DeepSeek 配置，模型资源固定到 `OPENAI_COMPATIBLE / deepseek-flash`，地址为 `https://api.deepseek.com`，凭证通过环境变量引用。发送内容为合成业务需求、角色上下文、测试供应商资料和正常工具 schema；文档与代码不记录密钥。

完整产品浏览器验证另外启动隔离 Core/Runtime 数据库、Redis 前缀和 Temporal 队列，使用完整 Spring 应用的开发登录、管理页、接待页、Task 页及真实 DeepSeek。它不借用端到端 harness 的简化身份入口。

浏览器完成管理员配置、第一项培训工作和第二项晨检工作、专业实例直接澄清、自然语言返工/确认、页面返工自动唤醒原提交者、同一成果更新到第 3 版并再次提交、BUSINESS_USER 最终确认，以及接待暂停/恢复。普通业务用户只显示协作入口，管理配置不出现在其侧栏。消息分页另外使用明确标记的 105 条合成历史 fixture，验证首屏 100 条、向前翻页和实时刷新不丢已加载历史；这部分不计作模型生成对话。

## 3. 场景证据

“真实模型”表示模型实际组织工具调用；“确定性 E2E”使用可重复的模型响应，但其后的服务和持久化链路是真实的。“SQL/Worker”为明确故障、权限和并发分支的集成验证，不代表对应外部服务已经在线联调。

| 场景 | 验证结果与范围 |
| --- | --- |
| E01 供应商调研 | 确定性 E2E 和真实 DeepSeek：接待建 Task、委派独立实例、HTTP 供应商工具、发布 ARTIFACT、提交、返回原入口、人确认。 |
| E02 同入口多项工作 | 真实 DeepSeek 与浏览器均使用同一个接待实例，创建独立 Task 与专业实例；历史、输入与结果分别关联。 |
| E03 多角色协作及子工作 | Agent/Task SQL 集成覆盖同模板不同角色、独立身份、直接消息、子工作发起和确认；E12 另有实际审核实例读写链。不将这些证据声称为四个真实模型角色同时完成复杂组织决策。 |
| E04 内外参与与范围 | E2E 使用 sponsor、partner、observer 三个人类身份和专业实例，核对明确共享范围与私有历史拒绝；渠道 SQL 测试核对真实身份绑定与伪造拒绝。 |
| E05 人工补充 | 真实 DeepSeek 先提出缺失期限，收到人答复后在原专业实例继续；浏览器验证专业实例直问直答及回复目标。 |
| E06 返工与确认 | 真实 DeepSeek 经 REQUEST_CHANGES、原实例修订、再次提交和明确确认；浏览器核对成果修订与最终 COMPLETED。决定保留人的原消息、代理实例和版本。 |
| E07 越权与撤销 | SQL/Runtime/HTTP 集成覆盖伪造确认、旧来源消息、转授越界、父授权撤销、私有 Session、当前资源授权和错误内部 token。 |
| E08 长期职责与安排 | E2E 定时实际唤醒；SQL 验证资源事件订阅与权限；Python 验证摘要来源、上下文预算、完整回执分页及持久记录不受缓存 TTL 影响。 |
| E09 重启与恢复 | E2E 实际重启 Python；独立 PG/Redis 集成重建存储实例、清缓存并恢复副作用回执。SQL/Temporal 故障注入覆盖启动回执丢失、取消、重复投递及旧 workflow ID 拒绝复用；未进行整个部署集群强制断电实验。 |
| E10 控制与迟到结果 | SQL/Worker 集成覆盖暂停、取消、关闭、早到恢复信号、丢失控制回执及迟到完成；真实完成内容和用量保留，终止工作不复活。浏览器核对接待暂停/恢复。 |
| E11 长流程工具 | E2E 实际 Temporal 人工等待、来源消息批准、Python 工具和完成唤醒；Worker 覆盖脚本/分支/外部等待/取消；真实 Sandbox Python、Node 成功与失败执行另行验证。外部回调使用可信测试扩展账号，非真实第三方业务供应商。 |
| E12 可用成果 | E2E 新审核实例按 TASK_CONTENT 版本引用读取真实报告正文、写审阅和来源修订；知识服务导入、索引、检索及扩展协议回归通过。未新增通用文档编辑或文件托管产品。 |
| E13 并发与旧成果 | E2E 旧 expectedRevision 返回冲突，模型重新读取后贡献；SQL 验证并发命令、来源版本和旧成果不能被确认到新内容上。 |
| E14 配置与直接使用 | 完整产品浏览器从空配置创建并发布模型、接待/执行角色及 Entry，随后直接交流和委派；授权管理、个人/组织归属另有接口回归。 |
| E15 跨相关 Task | E2E 把原专业实例加入第二个工作并继续工具操作；SQL 验证一个工作暂停、另一个仍可执行。 |
| E16 阶段交付 | E2E 同一长期 Task 两次 CONFIRM_STAGE 后仍可继续，并由定时消息再次推进；接待实例不结束。 |

## 5. 验证发现与已修正行为

- 两个 Agent 自动对 RESULT 相互致谢产生持续唤醒：改成按责任接收关系回报，新的请求必须显式发送。
- 实际 Spring 事务代理下直接读取 service 字段得到空值：调用侧统一通过实例方法访问服务依赖，并在真实事务链验证。
- 暂停/取消与启动、节点授权、完成回执互相竞态：持久控制意图、行锁顺序、423 效果前等待及独立完成回执共同处理。
- 长期工作把全部正文重复放入提示词：自动上下文改成摘要和版本引用，大结果明确省略并可分页取回原文。
- 模型把代理 sourceMessageId 放在业务 data 中：工具 schema 明确可信来源参数位置，错误可解释，不能被默默接受为自主确认。
- 模型工具参数 JSON 截断：保留原始参数和错误结果，已知 callId 的坏调用不产生副作用；模型可以缩短或拆分后重新提交，checkpoint 恢复不重做之前已完成的调用。
- 专业实例执行失败未反馈：失败形成持久通知，已有回执保留，后续处理不会自动盲重试外部写。

## 6. 当前边界

当前可运行形态为 alpha。完整企业组织管理、多租户商业交付、预算治理、性能/SLO 平台和角色自主进化不在本版范围。

本次没有真实 OIDC 提供方、飞书企业账号或第三方业务生产账号的完整在线验收；相应认证、渠道身份、回调、连接器与投递在协议和服务集成层验证。部署示例通过配置检查，不等于全部部署拓扑已经上线演练。模型会出现格式错误或业务理解偏差，权限、持久证据、明确失败及人的最终确认是实际运行边界。

## 7. 2026-10-25 试用问题回归

本轮针对重复回执、只回复进度后停止、临时失败需要人工催促，以及控制台样式问题，补充[运行收敛机制](activation-completion.md)。不是靠修改样例结果绕过执行链。

- Python 全工作区回归：237 通过、1 项依赖专门环境的持久化集成默认跳过；该项随后使用真实 PostgreSQL/Redis 与随机隔离数据库单独通过，实际核对重启后的累计用量、完成回执和换 call ID 仍不能重做未决写入。新增明确结束、进度停止后自动继续、显式回执抑制自动回复、同 Activation 续执行、累计用量、完成回执恢复、未决外部写入保护等用例。
- API 245 条通过；Worker 45 条中 43 通过、2 条 Sandbox smoke 默认跳过；Channel Gateway 185 条通过。覆盖同接收人重复工具调用、共享状态权限、生命周期与实际执行区分、传输重试、预算耗尽、等待不重试，以及提交失效与阶段说明保护。
- 确定性跨语言 E2E：10 通过、1 项显式启用的真实模型测试默认跳过。新增模型先说“开始工作”后自行继续真实工具调用、重复回执只投递一次；独立审阅后重新提交当前内容版本也经过实际 API/Runtime/Worker 链路。
- Web 13 个文件、62 条测试通过，类型检查和生产构建通过。三份 OpenAPI 的本地引用检查通过；共享 JVM 契约测试通过。

浏览器真实模型另用本地已有 DeepSeek 入口执行两项合成费用核算，凭证未写入文档。第一项“工作坊费用核对”自动完成了执行和独立审阅，暴露出审阅后未重新提交、把等待接受误写为 WAITING 的缺口；据此补充命令状态反馈、提交保护和通用执行提示，再运行独立场景验证。真实模型试用与上述默认跳过的 harness 测试分别记录，不能混为同一次测试。

最终版本的“培训物料核算”从一条自然语言需求开始，接待者创建工作、执行者写入费用表、独立审阅者读取实际正文并复算，协调者在审阅落库后提交最新版本。浏览器核对总支出 822 元、余额 178 元、审阅无必须修订项，Task 为 SUBMITTED，页面显示确认、返工与阶段确认入口；全程没有追加催促消息，最终接受留给用户。实例页显示生命周期与实际执行状态，未经授权不提供专业实例私有历史入口。

修复前停在进度回复的“社区开放日活动方案”也恢复到原实例：实际写入修订、原审阅者复核、再次返工、协调者核对并重新提交。一次恢复指令后全链路自行接续；中间出现的错误条目引用由模型依据工具错误自行修正。场地容量和备货口径仍列为业务待确认，不将模型提交当作现实活动已获批准。最终六项本地样例保留，所有 Activation 空闲后重载源码服务。
