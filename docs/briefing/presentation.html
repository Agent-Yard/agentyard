01

问题定义

企业智能体落地的共性问题

  • 智能体、知识、工具、模型配置分散
  • 运行直接依赖草稿配置，缺少稳定发布锚点
  • 多智能体协作链路难回溯、难解释
  • 自动化、人工处理和站外交互缺少平滑衔接
  • 资源复用、版本控制、影响分析能力不足
  • 业务侧、开发侧、运营侧对系统对象理解不统一

Lynxus 当前解决思路

  • 治理结构：业务域、场景、助手、智能体
  • 能力资产：Knowledge Base、Tool、LLM、Skill
  • 稳定运行：发布快照冻结资源和编排图
  • 执行承载：Temporal + agent runtime
  • 运行表达：会话、任务、流程、节点、恢复动作
  • 控制台串起配置治理、资源管理与运行观测

当前已落地能力

控制面治理

业务域、业务场景、助手、智能体、知识库、资源配置管理。

资源与知识治理

知识库、Tool、LLM Model、Skill 四类资源已打通，支持版本、生效版本、引用分析和删除影响预览。

发布冻结

助手发布时冻结资源版本、知识绑定、owner/session/playbook 策略和 playbook 定义。

Session 主状态机

支持当前 owner、shared state、handoff、idle timer 与 playbook 生命周期管理。

长流程托管

基于 Temporal 实现 `SessionWorkflow` 与 `PlaybookWorkflow` 的长流程托管、等待与恢复。

运行观测

当前 owner、session event、playbook run、handoff 和 shared state 可回看；session 级 SSE 已接入，失败可降级轮询。

知识工作台

已支持文件导入、URL 导入、导入任务、索引快照、检索验证和发布版本。

本地联调闭环

控制台、API、Channel Gateway、Worker、Knowledge Service、Agent Runtime 和基础依赖可在本地一次拉通。

认证与会话

控制台已切到 API 托管 Session，OIDC 入口已预留，本地开发保留 bootstrap 登录旁路。

后续补齐权限、细粒度观测、审计和成本治理时，不需要推翻当前架构主线。

08

关键设计取舍

发布快照作为执行锚点

优先解决配置漂移和运行回溯问题；当前运行只基于已发布 assistant release 启动。

知识库提升为一级治理对象

独立管理内容导入、索引快照、发布版本和引用关系，避免知识能力继续附着在助手草稿配置中。

Session 成为唯一会话控制中心

owner、handoff、idle timer、pending reevaluation 和 active playbook 全部收口到 `SessionWorkflow`。

Playbook 下沉为强流程子工作流

复杂业务流程由 child workflow 承担，owner 只负责是否调用与如何消费结果。

命令受理与结果观测解耦

运行入口先提交命令，再通过 session detail / session SSE 观察结果，避免 API 同步等待首个业务结果。

保留长期平台边界

虽然当前默认单租户且开发态保留 bootstrap 登录旁路，但对象模型和职责划分已为后续多租户与正式治理预留边界。

09

当前边界与不足

原型边界

  • 默认单租户，复杂租户治理仅保留模型边界
  • 认证已具备 API Session 与 OIDC 边界，开发态仍保留 bootstrap 登录旁路
  • 运行态主投影已落 PostgreSQL，API 读取 session 时会按需向 Temporal 校验 workflow 是否仍开放
  • 运行入口已改为 session-runtime 异步受理返回，前端通过 session SSE 观测变化，并保留轮询降级
  • external interaction 已入模，但 provider 与 callback 治理仍待继续补齐

生产化缺口

  • 细粒度权限、多租户与跨域共享治理尚未成体系
  • 审计、安全隔离、灰度发布、SLO、成本治理尚未成体系
  • pgvector / S3-compatible object storage 的正式职责仍待进一步收敛
  • CI、测试、备份恢复和环境一致性能力仍需补强
  • 运行观测仍缺长会话分页、派生视图和更细粒度订阅
当前最准确的定义仍是平台原型或 Alpha 骨架，不宜直接作为生产可交付平台表述。
